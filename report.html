1. Project Title

SENTINEL-X: Enterprise-Style Detection Engineering & SOC Automation (SIEM/SOAR) Platform

2. Why Did You Choose This Project?

Modern enterprise Security Operations Centers (SOCs) ingest massive volumes of heterogeneous logs (Linux, Windows Active Directory, network firewalls). Manually analyzing disparate logs causes severe alert fatigue and elevates Mean Time to Detect (MTTD) and Respond (MTTR). I chose this project to gain comprehensive, hands-on experience in Detection Engineering, SIEM normalization, and SOAR automation—the core disciplines utilized by Tier-1 defense teams (CrowdStrike, Splunk, Palo Alto Cortex). Building this platform directly bridges theoretical cybersecurity concepts with adversary behavior through the MITRE ATT&CK® framework.

3. Technologies & Tools Used

Backend: Python 3.15, FastAPI (Asynchronous REST API)
Log Schema: OCSF / Elastic Common Schema (ECS)
Detection Rules: YAML Sigma-style rules, Sliding Windows
Database: SQLite with persistent JSON indexing
Threat Intel: Offline GeoIP, ASN, C2 DB, CMDB Asset Inventory
Frontend UI: Cyber SOC Dashboard (Tailwind CSS, Chart.js)

4. How You Completed the Project (Approach & Methodology)

I structured and executed the platform through a modular 6-stage engineering lifecycle:

  • Ingestion & Unified Normalization: Engineered regex & key-value parsers for Linux auth.log, Windows Security Events (4624, 4625, 4688), and Zeek/Web logs, transforming raw text into standardized NormalizedEvent objects.
  • Rule Authoring & Stateful Detection: Authored 9 multi-domain rules covering Authentication, Endpoint, and Network vectors with an in-memory sliding window manager supporting both immediate triggers and thresholding (≥ 5 events / 60s).
  • Automated Context Enrichment: Integrated an enrichment engine computing composite risk scores (0–100) using Threat Intelligence (Tor exit nodes, C2 indicators) and internal CMDB asset criticality (Tier-0 Domain Controller vs Workstation).
  • SOC Incident Management: Structured an automated ticketing engine generating INC-2026-XXXX tickets with correlated raw evidence, chronological attack timelines, and MITRE ATT&CK tags.
  • SOAR Playbook Automation: Implemented automated containment playbooks (Perimeter Firewall IP drops, EDR network host isolation, Active Directory account lockout) with comprehensive audit trails.
  • SOC Operations Dashboard & Simulator: Developed an interactive dark-mode UI with live metrics, MITRE heatmap, and a 1-click Attack Simulator replaying real-world attack scenarios.

5. What You Learned (Key Technical Skills & Concepts Gained)

  • Detection Engineering Lifecycle: Practical rule creation, threshold tuning, and false-positive suppression.
  • Stateful Stream Correlation: Managing in-memory sliding time windows and cooldowns to mitigate alert storms.
  • MITRE ATT&CK® Mapping: Mapping signatures to tactics (T1110.001 Brute Force, T1059.001 PowerShell, T1003.001 LSASS).
  • SOAR & Incident Response: Closed-loop playbooks slashing containment response times from hours to milliseconds.

6. Challenges Faced & Solutions

Challenge Root Cause Engineering Solution
Disparate Log Formats Heterogeneous syntax across Windows EVTX, Linux syslog, and Zeek. Developed lookahead regex parsers normalizing raw strings into OCSF standard schema.
Alert Fatigue & Floods High-frequency attacks triggered duplicate tickets per attempt. Engineered sliding-window state pruning with a 30-second entity suppression window.
Python 3.15 C Extensions Standard PyYAML lacked pre-built binary wheels on Windows. Integrated pure-Python StrictYAML, ensuring zero-compiler portability and stability.

7. Final Outcome

Successfully engineered a fully functional, self-contained Enterprise SOC & Detection Platform with 100% automated Log → Detection → Alert → Enrichment → Incident Ticket → SOAR Containment pipeline, an interactive dark-mode Web Operations Center running at http://localhost:8000, a 1-click attack simulation center, and 11/11 automated unit and integration tests passing in under 1 second.
